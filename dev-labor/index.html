Verstehe die häufigsten Web-Angriffe — und wie du sie verhinderst. Alles läuft lokal, kein echter Angriff.

⚠️ 1. Cross-Site Scripting (XSS) OWASP #3

Angreifer schleust JavaScript in eine Webseite ein. Wenn die App Nutzereingaben ohne Bereinigung ausgibt, wird der Code im Browser des Opfers ausgeführt.

❌ Verwundbar
// Direkte HTML-Ausgabe — gefährlich!
div.innerHTML = userInput;

// Angreifer gibt ein:
// <img src=x onerror="alert('XSS')">
✅ Sicher
// Text-Node oder textContent
div.textContent = userInput;

// Oder escapen:
function esc(s){
return s.replace(/&/g,'&amp;')
.replace(/</g,'&lt;')
.replace(/>/g,'&gt;');
}

✅ textContent (sicher)

⚠️ 2. SQL Injection OWASP #1

Angreifer manipuliert SQL-Abfragen durch Nutzereingaben. Kann zur Datenbankübernahme oder Datenleck führen.

❌ Verwundbar (Python)
username = "admin' OR '1'='1"

# Generierte Query:
# SELECT * FROM users
# WHERE name='admin' OR '1'='1'
# → gibt ALLE Nutzer zurück!
✅ Sicher — Prepared Statements
cursor.execute(
"SELECT * FROM users
WHERE name = ?",
(username,) # Parameter separat
)

# Kein String-Concat = sicher!

🔐 3. Passwort-Sicherheit

Schwache Hashing-Algorithmen (MD5, SHA1) können mit Rainbow-Tables geknackt werden. Immer bcrypt oder Argon2 verwenden.

❌ Unsicher
import hashlib
hash = hashlib.md5(
password.encode()
).hexdigest()
# MD5 ist geknackt!
✅ Sicher
import bcrypt
salt = bcrypt.gensalt()
hash = bcrypt.hashpw(
password.encode(), salt
)
# bcrypt mit Salt = sicher

⚠️ 4. CSRF — Cross-Site Request Forgery OWASP #5

Eine fremde Seite löst im Hintergrund eine Aktion auf einer anderen Seite aus, bei der du eingeloggt bist.

❌ Angreifer-Seite (HTML)
<!-- Verstecktes Formular -->
<form action="bank.de/transfer"
method="POST">
<input name="to" value="hacker">
<input name="amount" value="1000">
</form>
<script>document.forms[0].submit()</script>
✅ Schutz: CSRF-Token
# Server generiert einmaligen Token
csrf_token = secrets.token_hex(32)
session['csrf'] = csrf_token

# Formular enthält Token
# <input type="hidden"
# name="csrf" value="{{ token }}">

# Server prüft Token bei POST
